## 2. 判定与产出

### 2.1 踩坑（已写入 `agent.md`）

1. 先出包后提交 → 版本登记的构建 commit 带 `-dirty`，包不可复现。
2. 验收中用 BACK 退出本应用会落到下层应用，被误读为「别人抢前台」；未先确认手机空闲。

### 2.2 风险（已写入 `docs/risks.md`）

- R22：`-dirty` 构建不可复现。
- R23：真机验收可被前台占用打断；本轮 OPPO 前台截图与应用内版本号缺失由用户本人确认验收通过补齐，风险条目保留。

### 2.3 上收候选（给中央管家）

- 规则：**出包顺序硬约束**——版本号 bump、功能改动必须先本地提交，再 `assembleRelease` 并登记；登记脚本报 `-dirty` 时该版本不得当作可复现版本对外分发。
- 规则：**真机验收的「前台确认」动作改为只读**——用 `am start` + `dumpsys activity activities | grep topResumedActivity` 取证，不用 BACK 退出应用；发现前台变化先判断是谁启动的（`dumpsys` 任务栈 + 时间），再决定停手。
- 落点建议：并入 `android-true-device-qa-orchestrator-local-zh` 的收尾回执与 `version-registry-local-zh` 的失败处理，不新建 skill。

### 2.4 自动化候选

本轮未发现「主动型、周期重复」的新增手工活；两次踩坑都是一次性流程约束，走规则/skill 机制二更合适，故不新增自动化。

### 2.5 口令优化

- 改前：`版本 bump 后出包`
- 改后：`版本 bump 后先提交再出包`
- 理由：一句话消掉 dirty 构建的歧义。

## 3. 可复用资产

- 三按钮状态机写法（toggle 展开 + 主按钮语义切换 + 可逆回退）可作为本项目后续「多保存路径」表单的模板。
- 真机补录验收判据三条（选中过去日期 / 保存后日期相等 / 今天路径不变）可直接复用到其他「时间补录」类需求。
